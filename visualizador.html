O que o visualizador nos ensina sobre Trunk-Based?

Trunk-Based Development não é apenas uma convenção de nomenclatura — é uma disciplina de integração contínua.

1. A Linha Central é Sagrada

No gráfico, repare como o tronco principal verde nunca para. Não existem branches de release congelando o desenvolvimento. A main é a versão viva do produto em produção.

2. Branches Curtas (< 24h)

Quando uma branch é criada para uma feature maior, ela se reconecta quase imediatamente. Quanto menor o tempo de vida da branch, menor a probabilidade de conflito com commits de colegas.

3. Reversões são Bem-Vindas

Se a CI falhar ou um bug for detectado, um simples git revert <sha> desfaz o problema sem reescrever o histórico compartilhado nem bloquear a turma.
